# 原生实现方案与分工

## 已确定的方向

最终交付为 **原生 Android APK**。使用 Kotlin，应用界面以 Compose 为主；PDF 页面与手写输入走适合低延迟输入的原生渲染层。目标是读写、保存和系统集成可靠，不把浏览器预览状态当作正式笔记格式。

- 固定应用 ID 的建议值：`io.github.dpan538.annota`。在首个可分发签名包产生前定稿，之后不随意改名。
- 元数据使用本地事务数据库；PDF、图片与笔迹资源放应用私有目录。文件写入先暂存、校验，再原子提交索引。
- 原 PDF 与批注层分开保存。页面顺序与旋转属于文档元数据，导出时合成。
- PDF 引擎先验证系统 PdfRenderer/AndroidX PDF 的实际能力与目标系统兼容性，再锁定实现；渲染、选字和导出通过接口隔离，不预先宣称一个未测引擎能覆盖全部需求。
- 触控笔按系统真实能力接入，不凭型号名称启用震动或双击。未知型号保留标准笔输入路径。
- 字典使用打包 SQLite，后台只读查询；界面层隔离过期请求，不联网补全释义。
- 更新与匿名反馈是独立网络模块，不能被阅读、笔迹和查词代码隐式调用。

依赖版本、minSdk、targetSdk 与性能指标由原生任务依据真实设备和官方文档确认，不把设计稿像素当作 Android dp。

## 两个任务的边界

| 设计与规划窗口 | Android 实现窗口 |
| --- | --- |
| 用户流程、版式、配色、Logo、文案与指南 | 工程、PDF、数据库、存储、原生绘制与输入 |
| README、许可、发布说明与首次上传 | 离线词典接入、反馈服务与更新安装实现 |
| 加载/失败/取消/空状态设计与验收标准 | 构建测试 APK、自动化验证及真机状态记录 |
| `design/`、`branding/`、工程规划文档 | `android/`、`feedback-service/` 与实现状态记录 |

原生任务采用用户指定的 GPT-6.1 Sol / Extra High。独立任务仍在推进，不因交接就标记功能完成；测试包、正式签名包、GitHub Release 分别记录。

## 必须保持的产品约束

- 无账号、云同步和默认联网；不加入遥测或远程字体。
- 单行顶部三个独立分区；侧栏按需显示，双页是两张完整页面并排。
- 纸张只提供四种纹理、三种底色；应用外观只保留四套既定主题。
- 照片和文件选择由系统提供；字典手写使用系统 IME，并单独验证其离线行为。
- 卸载会影响应用私有数据；正式发布前给出明确的本地备份与恢复方式，关闭应用云备份链路。
- 不能以合成触控事件通过代替 Focus Pen Pro 等实际硬件验收。

原型桥接事件与细节见 [`design/NATIVE-INTEGRATION.md`](../design/NATIVE-INTEGRATION.md)。
