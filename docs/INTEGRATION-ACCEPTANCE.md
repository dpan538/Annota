## 反馈（按最新要求改为自动提交）

App 填写 → 点击唯一“提交反馈”按钮 → HTTPS Vercel 接收服务 → GitHub API 创建公开 Issue → 返回本次请求的真实 Issue URL → App 自动弹出“已收到反馈”。不跳浏览器、不需要 GitHub 用户登录、不显示“检查提交结果”。网络或服务失败只提示失败并保留草稿；并发点击被禁用，新编辑内容不会被旧回执清除。

接收层只返回 GitHub 的真实成功回执；未知字段、超长正文、请求身份冲突、无效/其他仓库 URL、GitHub 拒绝/超时都不会返回成功。重试先按相同请求标记读取 GitHub（最近 500 条 Issue，含关闭条目）；同一实例内串行提交。跨实例同时提交和超过窗口后的重试不提供严格 exactly-once 保证。每仓库每小时保守限制 20 条，避免无限匿名写入。

Vercel 项目 `annota-feedback`，当前部署 `dpl_Lg5iZ5D2zsZvBrkRsyqZiEiDTQw4` 已 READY。用户授权仅生产接口公开，预览保留登录保护；用户配置的生产 Secret 名称 `NNOTA_GITHUB_TOKEN` 按原名保留，由服务端兼容读取，凭据从未进入 APK 或仓库。

## 桌面小组件

“Annota · 继续阅读”：标题、页码、整卡点击恢复精细阅读位置。支持横向/纵向调整大小、系统深色模式、大字体时收紧上下内边距。读取本地状态，没有网络、后台轮询或 PDF 位图缓存。最近文档删除/移入废纸篓后回到书库。

使用真实 `AppWidgetHost` 绑定 RemoteViews，验证小尺寸/宽尺寸、点击恢复《Attention Is All You Need》第 4 页与精细位置、废纸篓回退。宿主是测试 Activity，不声称已覆盖所有厂商桌面。

## 外部 PDF

声明 PDF 的 ACTION_VIEW 与 ACTION_SEND；接收 content/file URI，流式复制到私有存储，验证 PDF 内容、页数与权限。复用现有任务的暖启动、不重复导入同一外部文件、密码输入、取消/失败清理、导入/导出页面进度。没有全盘文件权限或网络文件抓取。

测试 APK 内的发送器用独立 UID 和私有 ContentProvider 提供临时读权限；原始 Attention 论文导入后校验 SHA-256、页数和重复分享。该机制可用于微信/QQ 提供的“其他应用打开/分享”，没有声称在未安装的微信/QQ 客户端上实测过。

## 交互补齐

书库 Filter 常驻为无色块纯图标，展开为锚定小菜单，保留主页/收藏/废纸篓、文件夹、搜索与滚动上下文。菜单/导航侧栏采用短线性局部过渡；不对整份 PDF 做淡出或重建。

页面侧栏增加页码跳转与按页批注笔迹预览，点击定位原文，搜索与返回位置在 Activity 重建后恢复。系统返回依次关闭键盘、小菜单、导航侧栏，再返回书库。阅读顶栏中间继续留空；选区继续只用“复制 / 查询”文字。
