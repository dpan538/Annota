# 项目空间与归档

源码、随 APK 分发的离线资源、许可、当前回归测试和版本验收记录属于维护资料，应保留在项目中。测试代码按回归价值维护，不仅按文件日期删除。

## 可归档的本地产物

| 目录或文件 | 处理方式 | 恢复影响 |
| --- | --- | --- |
| `android/app/build/` | 构建结束后可归档并清理 | 下次构建重新生成 |
| `android/dist/` 的旧版 APK | GitHub Release 与备份核验后清理，保留当前版 | 可从对应 Release 或备份恢复 |
| `.tooling` 中历史测试 APK、截图、临时数据库、日志及旧版本辅助脚本 | 完整备份后归档 | 复查旧实验时恢复对应文件 |
| Gradle 版本派生缓存和已停止的 daemon 日志 | 保留依赖模块与 wrapper 后清理 | 下次构建会重新生成缓存 |
| 词库研究原始下载、研究虚拟环境和绘图环境 | 归档，不影响已经随 APK 分发的资源 | 重建研究数据前恢复环境和原始材料 |
| 旧本地设计工作区 | 完整备份后归档 | 需要原始材料时恢复 |

签名资料、当前源码和离线资源不属于可再下载缓存。共享 SDK/JDK 的符号链接和当前测试模拟器数据应单独保留，不能随旧测试产物一并删除。私有归档和签名内容不得上传仓库。

## 归档步骤

1. 停止本项目的构建守护进程及专用测试模拟器，避免备份期间数据变动。
2. 在外部存储建立完整项目备份，包含隐藏文件和 Git 历史。使用保留权限及符号链接的归档格式；外部共享工具链不随符号链接重复复制。
3. 记录文件清单、文件 SHA-256、符号链接目标和压缩包 SHA-256，逐文件读取归档核对。
4. 删除前再次检查选定原件与已验证备份一致；只清理清单列出的路径。
5. 保留本地恢复索引，记录归档位置、清理范围和前后占用。后续构建会重新产生缓存，应在阶段交付后再整理。

历史公开 APK 以 [GitHub Releases](https://github.com/dpan538/Annota/releases) 为准。私有完整备份需在维护者自己的存储中恢复；完整恢复应先解压到独立目录，避免覆盖后续修改。
