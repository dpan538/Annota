Page-Picture Ink Cache · 按页笔迹 Picture 缓存

Status: preview · version 1.2.1.2 · updated 2026-11-08 renderingperformancecacheink

What it is. Completed page ink is recorded once as a page-space Picture and replayed as one canvas op per frame; steady-state writing frames are 2.0–2.9× cheaper with zero changed pixels.

Problem it solves

Replaying every completed mark as a drawPath on every frame made long annotated pages expensive while writing or scrolling.

How it works

Each page records a page-space display list, keyed by page id and ink version, and invalidated precisely when a stroke/erase/undo/selection change touches that page. The frame that records the list paints the marks directly; later frames replay one drawPicture op. Frame plans, placements and matrices are cached and updated in place for pure pans.

Difference from existing approaches

The cache is page-space and vector, so it replays correctly at any zoom and keeps screen/PDF geometry identical. Invalidations are driven by explicit page ink versions rather than heuristic dirty rectangles.

Limitations

  • First frame after a page change pays display-list recording (25–90% slower on software canvas)
  • Pictures use native memory outside the LRU page budget
