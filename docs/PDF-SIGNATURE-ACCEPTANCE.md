# PDF 手写签名与已签名文件兼容性 · 1.0.2 正式版

本次更新实现手写签名，不提供证书数字签名或证书信任验证。正式版通过 [GitHub Release](https://github.com/dpan538/Annota/releases/tag/v1.0.2) 分发 APK、校验文件和应用内更新清单。

## 用户流程

阅读页「更多 → 手写签名」打开签名画布。支持手指和标准 Android 手写笔输入，撤销、清空与取消；手写笔事件优先于同时触碰的手掌。

「放入文档」后，拖动签名移动，拖右下角调整大小，保持签名比例。确认后保存为透明图片批注，跟随本地文档、撤销/重做、备份和 PDF 导出。取消、离开页面或关闭未确认的画布不会保存签名模板。

## PDF 兼容性与原件

- 不再把“允许修改且允许提取文字”作为导入前提。可阅读的受限 PDF 可以只读导入；禁止提取文字时不提供选字和搜索结果。
- 允许批注但禁止整体修改或提取文字的 PDF 可以使用批注与手写签名。
- 检测已有数字签名与 DocMDP 修改权限。限制批注的文档保持只读，界面不提供编辑工具。
- 加密 PDF 在用户输入正确密码后生成私有阅读副本，源文件字节保持不变；不保存密码。阅读副本与源文件一起参与本地备份和恢复。
- 没有页面或批注改动时直接导出原始字节，保留原件中的数字签名。
- 已签名 PDF 增加批注后，导出前提示这是新副本。导出将已有表单/签名外观绘入页面，不将新副本标记为原数字签名有效。原始文件不改写。
- 数据库从版本 1 迁移到 2，新增独立的 PDF 权限和阅读副本元数据；原有笔迹与撤销历史保留。

不承诺兼容所有第三方 PDF 扩展、损坏文件或动态 XFA 表单。若仍有无法打开的文件，需要用该文件复现，不能仅凭“带签名”判断具体格式问题。

## 验证

`PdfSignatureTest` 使用本地生成的 RSA/SHA-256、PKCS#7 detached 签名夹具，并实际验证 CMS 摘要与签名；测试证书不用于模拟受信任的签署身份。

验证内容包括签名原件字节一致、可见签名外观、批注副本、加密和只读文件、批注权限与文字提取权限分离、本地备份恢复、版本 1 书库迁移、手写签名的透明度/放置/撤销/导出重开，以及独立虚拟显示器上的原生签名界面流程。

测试设备为 API 36 模拟器；合成触摸/手写笔事件是输入回归，不代表小米真机笔感验收。测试仅新装 Annota 的独立应用数据，不清理其他应用。原生界面截图和测试记录在 `android/verification/pdf-signature-1.0.2/`。

结果：完整回归 23 项通过；追加的原生拖动、等比缩放与确认流程 1 项通过。Debug、测试包、Lint 和非调试 Release 构建成功；安装证书与公开 1.0.1 一致。包身份、测试及公开交付校验记录见 `android/verification/pdf-signature-1.0.2/release.json`。

公开交付已验证：`v1.0.2` 为最新稳定 Release；APK、`SHA256SUMS.txt` 与 `annota-update.json` 均通过匿名下载和完整校验。公开 APK SHA-256 为 `c03189fd583a82075fa934fc1c0cd1cded26981a14704c3351825c3c554a53f7`，与通过验收的非调试构建一致。

新增签名流程的自动化验收来自模拟器；目标平板与具体待签文件的兼容性仍需实际使用复核，不以模拟器结果代替真机笔感。
