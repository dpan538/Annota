# Annota 1.2.1 候选构建记录（未发布）

> **状态：开发候选，未发布。** 本文件记录仓库中的 1.2.1 变更与本地候选构建验证，
> 不构成 Release、不更新默认更新通道。发布范围与版本号由维护者确认。

## 本候选的目标

1. 扩词前先给 en-zh 做别名冗余瘦身，释放体积并把查询路径改到 `entries.boundary_key`。
2. 用释放的空间扩充词语内容：把 WordNet/Wiktionary 已有中文义项反向生成汉英条目。
3. 继续打磨检索响应速度与英→中整句翻译质量。

## 检索与翻译

- 查询仍使用持久只读连接、Bloom 预筛、缓存；en-zh 边界匹配不再需要多表 join。
- 英→中整句翻译：解码仍为贪心；本轮只新增输出后处理（中文标点/空格/句末标点/空行规范化），
  不改变数字、拉丁词或专名。40 条固定开发集比较 greedy / no-repeat 4-gram / repetition
  penalty / early-EOS guard / beam 2–4 后，没有变体达到稳定改善，因此未用 beam 替换默认解码。
  详见下文“翻译质量”一节。
- 既有校准：人工规则提示主题冲突时不强行选单一义项；`set up` 与 `setup` 保持边界区分。

### 翻译质量（英→中，开发集结论）

- 开发集：`design/translation/evaluation/sentence-quality.json`，40 条自写英文 + 人工中文参考，
  覆盖日常/计算机/学术/法律/否定/数字/长句/多句。**这是开发集，不是准确率基准**；每句只有
  一条人工参考措辞，chrF 只表示与该措辞的接近程度。
- 方法：`design/translation/evaluate_variants.py`（numpy + onnxruntime + sentencepiece，完全离线）
  运行 8 个变体，输出 chrF、重复 n-gram、EOS/超时、逐句耗时与失败样例，报告在
  `design/translation/evaluation/variant-report.json`。
- 开发集结果（本机 macOS CPU，非平板耗时）：greedy 平均 chrF 39.11；no-repeat 4-gram 与
  early-EOS guard 对 40 句无任何变化；repetition penalty 39.34（3 胜 6 负 31 平，95% 区间含 0）；
  beam=4 40.70（12 胜 12 负，区间含 0，平均约 3.6 倍耗时）；beam=4+廉价策略 40.96
  （12 胜 13 负，约 3.6–5.3 倍耗时；本机运行间波动大）。40 句在所有变体上 EOS 完成率均为 100%，重复 4-gram
  比例为 0，未观察到截断/超时。
- 结论：不采用 beam/惩罚/屏蔽作为默认解码；只新增输出后处理，在同一开发集把 greedy 的平均
  chrF 从 35.35（原始输出）提高到 39.11（仅标点/空格规范化，不是语义准确率提升）。
- 仍存限制：`cache miss`→“缓存错误”、`without prejudice`、`ticket`→“罚单”、数量/否定遗漏
  等模型层错误未被本轮修复；中→英仍为词典查询；开发集结果不能写成准确率。

## 已知限制

- 反向汉英条目是机器合并的等价表达，未经逐条人工校对；同一中文词最多 4 个英文等价词。
- 所有 SQLite 改为 `.pack` 后首次安装/升级的首次启动会多一次解压（模拟器实测 1,208 ms）；
  若目标平板回退明显，可改为按需懒加载。
- 手写 P1 首帧多出 Picture 记录成本（软件画布 25–90%）；P3 v5 收笔几何 taper 依赖抬笔压感跌幅，
  单点帽径约为 v4 的 72%；真机手感仍需实测。
- 翻译质量改进仅针对英→中；中→英仍为词典查询。完整评测结论见
  `design/translation/evaluation/variant-report.json` 与研究报告。
