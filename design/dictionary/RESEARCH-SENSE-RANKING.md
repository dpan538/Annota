# 离线词义排序：来源审计、对照评估与实施顺序

2026-11-04；1.1.1 词义排序前期研究（后续已加入向量方案，见下）。研究子任务仅审计资料；父任务已将相应程序改进集成，实测结果见 [验证记录](../../android/verification/sense-ranking-111/)。最终交付见 [发布记录](../../docs/1.1.1-RELEASE-NOTES.md)。数据库数字对应 `evaluation/sense-inventory-audit.json` 中三个 SHA-256，后续重建须重新审计。

## 后续实施

维护者随后确认本次 1.1.1 纳入本地向量方案。已集成随 APK 提供的 MiniLM、固定释义索引、双线程 CPU、PDF 打开预热、持久语境缓存，以及可关闭向量优化的设置；普通词典保留。前期建议与限制保留供审计，当前实现、模型来源和专项诊断见 [semantic](semantic/) 与 [最终语义验证](../../android/verification/semantic-111/)。相似度并非准确率，不足以修复错译或缺失义项。

## 结论

优先做 **保留完整义项 → 跨库统一比较 → 有拒绝机制的加权释义匹配 → 源质量纠错**。不要先引入大型 WSD 模型掩盖词库中的错译，也不要将“查到词头”当作“语境正确”。神经方案值得作为独立离线实验，但必须同时证明中文候选质量、误提升率和设备延迟收益。

- 本轮可实施：保留 `source + synset/gloss + pos` 身份，禁止只按中文去重；全部来源一起排序；同词形证据合并；距离权重、候选间区分度、释义长度抑制；证据不够就显示普通释义，不标“当前语境”。
- 下一轮优先：导入 WordNet `index.sense` 的稳定 sense key / tag count、词性与词义领域。将候选对齐与来源错误做成可审计资料，不能把 ECDICT 的英文段落与中文逗号项按位置配对。
- 备选实验：冻结 Apache-2.0 的 MiniLM ARM64 量化模型，给**已有且可靠的义项**离线重排；先离线评估，不直接改变正式版默认行为。模型和索引全部进 APK，绝无首次联网下载。

## 1. 当前库有什么，以及缺什么

只读脚本：`python3 design/dictionary/evaluation/audit_sense_inventory.py`。报告保留全部被测词的原始候选；不包含运行时预测，不声称测得应用准确率。

| 数据 | 当前快照 | 对词义排序的意义 |
| --- | --- | --- |
| 主词库 en-zh | 771,180 条记录，160,511 条非空英文 definition | 总数含多个来源，不是 77 万个独立英汉义项；translation / definition 缺少一一对应的 sense ID。 |
| Wiktionary 汉译 senses | 61,076 条 / 48,077 词头，8,229 词头多义 | 全部有 gloss；930 组同 word+POS+rank 重复，rank 是提取顺序，不能当作跨词源、跨来源频率。 |
| WordNet-COW | 77,708 条 / 61,340 词头，8,648 词头多义 | 全部有 gloss，但仅保留 COW 提供汉译的 synset 子集；不能等同完整 WordNet 候选集。 |
| 同中文、不同英文义项 | Wiki 1,488 组；WordNet 546 组 | 审计时 `distinctBy(word+label+text)` 会丢候选；应至少加入 gloss/source，长期保留 synset/sense key。这些组不是全部错误，也不是应一律删除的重复数据。 |

WordNet 的义项编号有语料频率基础，但只针对被标注的义项；未标注义项排在后面，编号不是当代技术英语的使用概率。构建器目前保留 rank，却丢掉 tag count、语义关系图和领域指针。恢复这些字段比为每份用户 PDF 新增固定规则更通用。[官方数据库格式](https://wordnet.princeton.edu/documentation/wndb5wn)、[稳定 sense key 与 tag count](https://wordnet.princeton.edu/documentation/senseidx5wn)。

### 来源错误与排序错误要分开

| 检索 | 审计证据 | 处理 |
| --- | --- | --- |
| bank | ECDICT 英文 definition 的首项是河岸，中文 translation 首项是银行 | 两列不能按顺序逐项对齐；否则会制造“河岸语境→银行”的假监督数据。 |
| measured | COW `02931947-a` 中文“定量的”，gloss 实际是音符具有固定节奏值 | 这是源映射/译义问题；即使 WSD 找对英文义项也会输出错中文。先隔离疑似错误映射，查原始来源再修订。 |
| culture | `14459824-n` 英文是精致/完善状态，中文混入“培养；栽培” | 不能因为后面也有“精致”就判整条合格；用户看到的首要译义仍可能错。 |
| significant | `02165655-a` 英文指与偶然因素不能解释的相关性，中文只有“有意义的” | 统计语境需要“显著”的准确对应；排序正确但汉译不充分，计为源质量问题。 |
| mean | 算术平均值存在于 ECDICT 中文，但精确 Wiki/WordNet 汉译候选中没有相应名词义 | 这是结构化候选缺口；不要用缺失候选集评价 WSD 能否正确选中。 |
| related | Wiki/COW 有“有关/关联”，ECDICT 首项偏“讲述/叙述” | 候选存在时是默认展示及排序问题，适合程序处理。 |

以上是源数据审计例，**不是建议为这几个词写永久硬编码规则**。纠错应以 `source + revision + sense identity + evidence` 记录，保留原始源，不静默修改来源或伪造第三方释义。

## 2. 当前算法审计边界

初审的旧逻辑按单库 gloss 的重合词个数排序，两个命中且领先就标 contextual。它容易受长释义、例句和重复屈折词影响。任务期间父任务已加入 `SenseRanker.kt`：候选词局部 IDF、邻近距离、长度抑制、重叠词形证据合并、领先差距与拒绝机制，并已合并跨库排序。本报告不把初审问题冒充修改后实测结论。

仍须验证的结构性边界：

1. **同义项重复不等于独立证据**：同一 synset 多中文译名、同一释义来自两个来源，不能投两票；相反，不同 gloss 却相同中文的义项不能提前合并。
2. **例句不应与定义同权**：WordNet gloss 同时包含定义和例句。generic “significant” 的例句中就可能包含 statistically，诱导过宽义项胜过统计义项。可以构建时区分定义与例句，保留两者并降低例句权重。
3. **否定、转折和另一个话题**：`electric charge rather than the fee paid for a service` 的后半句有更多收费关键词，但说明的是排除项。普通袋词算法不理解该关系。不要只靠加长窗口；明确转折/否定遇到多领域竞争时优先不提升。
4. **词性不是词义**：`to` 后常见动词但也可能是介词结构；一个局部词性提示不能直接宣称确定语境。POS 可减少候选，不代表已经解决同词性多义。
5. **PDF 上下文不等于整页词袋**：保留选区锚点、同栏同句；标题、两栏、表格及不同页需分开。人工构造的 before/after 评估只测试检索与排序，不测试 PDF 提取正确性。
6. **置信度不是分数别名**：加权重合分数、cosine 和模型 logits 都不能未经校准就解释为准确率。必须用保留评估集测“提升了多少、错提升多少”。

## 3. 开源路线比较

下列为一手资料核查；包体与速度估算明确区分，尚未进行 Android 基准。

| 路线 | 一手依据、许可 | 完全离线成本与判断 |
| --- | --- | --- |
| Lesk / 加权 gloss overlap | [NLTK 实现](https://www.nltk.org/_modules/nltk/wsd.html)，[Apache-2.0](https://github.com/nltk/nltk/blob/develop/LICENSE.txt) | 不需模型；成本随候选与 gloss 长度增长。官方简实现即使零重合也会返回最大项，不能直接用作“确定语境”。适合本轮 Kotlin 自实现加上明确拒绝，不需打包 Python/NLTK。 |
| UKB 图传播 | [作者论文](https://aclanthology.org/E09-1005/)、[官方仓库](https://github.com/asoroa/ukb)、[GPLv3 源码许可](https://github.com/asoroa/ukb/blob/master/src/LICENSE) | Personalized PageRank 利用完整词汇关系图，能补词面不重合。但当前裁剪库没有图，需要新增全图、POS/词形映射和移动端移植；官方说明平台为 Linux/macOS。GPLv3 不能直接当 MIT 组件塞进当前应用。先做独立研究基线，代码引入需单独评估许可与分发方式；本轮不引入。 |
| GlossBERT | [论文](https://aclanthology.org/D19-1355/)、[作者代码](https://github.com/HSLCY/GlossBERT)，仓库 MIT | 用 context-gloss 对做监督 WSD，逐候选推理；候选越多成本越高，不能全部预编码消除上下文交互。原仓库是旧 PyTorch 工具链，迁移/量化/移动端验证成本高。发布 checkpoint 位于外部 Drive；不能把代码 MIT 自动视为所有训练数据和外部权重已完成再分发核查。暂作为强研究对照。 |
| MiniLM 释义向量重排 | [官方模型卡](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2) Apache-2.0；[官方 ONNX 文件](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2/tree/main/onnx) | 384维，普通 ONNX 90.4 MB，ARM64 qint8 约23 MB（网页实际文件量级，不是完整APK增量）。预编码候选 gloss 后用户端仅编码局部语境，但它是通用句子相似度模型，不是经验证的 Annota WSD 模型；必须处理目标词定位、反例、中文对齐及分数校准。适合下一步受控实验。 |

向量存储估算：100,000 条义项 × 384 × 2字节（fp16）= 76.8 MB 原始向量；int8 约38.4 MB，另有量化参数、词义ID和索引。应先只给多义词的独立 gloss 建向量，且只比较所查词的候选，不引入全库 ANN 搜索。此处是算术估计，**不是已构建或实测资源量**。其许可、模型、tokenizer 与推理运行时 notices 也需随 APK 完整带上。

UKB/神经 WSD 只能在候选集合中选择；都不能修复不存在的汉译或把“培养”自动纠正成“修养”。短句/长词组翻译与词典 WSD 应保持独立结果类型，不能用生成译文补成未标识的字典义项。

## 4. 独立对照资料与评估方式

`evaluation/sense-ranking-cases.json` 共36条人工编写诊断句，包含 bank、cell、charge、culture、current、draft、field、solution、interest、mean、significant 等。覆盖普通阅读、生物、电学、统计、财务、法律、数据库；包含4条证据不足和3条干扰/否定。它是**工程诊断集，未经第二名标注者复核，不是公开金标基准**，不能用36条成功率宣传词典整体准确率。

字段：`query`、`before`、`after` 为文本；`expected` 为可接受中文关键词；`expectedGloss` 为英文语义检查线索（不是字面匹配金标）；`expectAbstain` 指不应标明确定语境，但普通词典结果仍可显示；`category/sourceIssue/rejectPrimary` 用于区分失败原因。`rejectPrimary` 仅在局部源错误例中提醒不要让错译排最前。

实际应用评估必须分别记录：

- 候选是否包含目标义项；若无，记 candidate-gap，不用它惩罚排序器。
- 最终首义项及候选列表、词性、来源、完整英文gloss、是否contextual；不能仅记录非空命中。
- “提升正确率”=正确提升/全部提升；“提升覆盖”=提升/证据充足且候选正确的样本；单列错误提升、保守拒绝和数据源问题。
- 证据不足四例必须无误提升；干扰例可保守拒绝，不能为了通过每条用例改成专词规则。
- 保留不参与调参的同词异境句和新词测试；评估集扩到多人复核后再固定验收阈值。
- 后续真实设备记录查词冷/热 p50/p95、内存峰值和取消旧查询情况；本子任务没有这些测量。

父任务负责运行真实 Android 查询并保存逐例结果；本报告的 `sense-inventory-audit.json` 仅证明数据快照与候选结构，不替代该结果。

## 5. 可直接执行的优先级

**P0，避免确定地给错解释**：保全 sense 身份、跨来源统一排名；取消所有低证据的 contextual 提升；测试相反词义和否定句；来源错译进入隔离/修订清单。普通词义仍完整可查，不以删除全部词义解决准确性。

**P1，改善普通阅读默认结果**：保留 WordNet tag count 与词性；Wiki 保留领域/usage/词源而非只剩 rank；ECDICT 原始多义文本保留原样，未经验证不要做英中按序配对。来源间按语义证据合并，避免某个来源固定压住另一来源的正确释义。

**P2，便宜的语义扩展**：尝试受限的同义词/上位词 signature，但只扩一跳、低权重且去重；保留独立留出反例集。扩展会增加误匹配，不能默认“越多越好”。

**P3，模型实验**：先将23 MB级别 MiniLM 作为候选重排实验，与保守加权 Lesk、普通默认顺序对照。没有显著降低错误提升，或者设备延迟/包体不合适，就不合入。UKB和GlossBERT不作为本轮紧急修复依赖。

## 6. 本轮实施范围与剩余边界

已自实现加权 Lesk，并接入中英释义展示。相对每个竞争组至少需要两条独立差异线索、绝对与相对领先差距；否则保留默认顺序。相同定义/POS合组，中文相同但定义不同的记录完整保留。一次排序共享只读 SQLite 连接与词形缓存，避免逐词开库。

近邻否定/排除标记、限定词短语与动词义冲突会阻止提升。这是保守规则，不是句法分析；否定其实修饰其他从句时也可能降低召回。旧的有限人工规则仍保留，但存在竞争线索时不按计数强行选中，且同样受否定及限定词短语词性门禁约束。已经通过规则确认的义项不会被未经复核的上游长词组覆盖；应用内已核对词组仍可提供更具体的解释。领域和动词提示仅作为默认排序，不标记已确认语境。自动扩词要求两个实质词（已核对的应用词组除外），不影响主动查询完整词组。

本轮没有修改上游译义、没有新增截图专用规则、没有引入 UKB/GlossBERT/MiniLM 模型。当前英文兜底在构建阶段每词最多保留三条定义，中文结构化候选亦受来源覆盖范围制约；因此“保全义项”指本次检索已加载候选，不等于完整收录原始 Wiktionary/WordNet。后续需要优先补齐义项身份、频率与可靠的英中映射，再独立评价语义模型。
